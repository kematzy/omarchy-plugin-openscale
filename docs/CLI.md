# The `osc` CLI — what this plugin depends on

Short reference for the external tool the widget shells out to. Everything here was read from the
installed binary's build metadata and observed network requests; no source is available.

## 1. The CLI itself

- **Name:** `openscale`, installed as `openscale` with an `osc` symlink.
- **`osc --help`:** lists the command surface; every command accepts `--json`, `--account <name>`
  and `--no-color`.
  - Usage: `openscale <command> [flags]` (osc for short)
  - Commands:
    - `login` - Sign in this device (opens the browser)
    - `logout` - Sign this device out and revoke its key
    - `whoami` - `Who and which account this device acts as
    - `account` - Your accounts and teams
    - `keys` - API keys
    - `models` - Models, context and price per 1M tokens
    - `chat` - Stream a reply (reads stdin when piped)
    - `setup` - Set up a coding agent with OpenScale
    - `batch` - Batch jobs
    - `balance` - Credits, burn rate and hours left
    - `claim` - Get more credits (opens the browser)
    - `usage` - Tokens and cost by model
    - `plan` - Your OpenScale Unlimited plan, running now
    - `limits` - Rate limits and your busiest minute
    - `sbx` - Sandboxes: create, run and reach them
    - `template` - Sandbox templates
    - `doctor` - Check sign-in, connection, clock and agent configs
    - `upgrade` - Update to the latest version
    - `version` - Print the version
    - `completion` - Shell completion script

- **Language:** Go, shipped as a **single statically linked, stripped binary** (no runtime, no libc).
- **Build:** Go 1.26.x, cross-compiled per OS/arch with `CGO_ENABLED=0` and `-trimpath`, from an
  untagged source tree (module version `(devel)`, no VCS stamping). The version string is baked
  into the source rather than injected with linker flags.
- **Module path:** `github.com/afgventura/openscale/cli`.
- **Source:** **private.** The module path does not resolve through `proxy.golang.org` or
  `pkg.go.dev`, and the repository is not publicly browsable. Only prebuilt release artefacts are
  published, plus a Homebrew tap whose formula is auto-generated by the vendor's release script.
- **Distribution:** versioned tarballs/zips per platform with a published `checksums.txt`; `osc upgrade`
  re-checks and replaces itself. Exact URLs and verification steps are below.
- **Credential storage:** the device key lives in the OS keyring (libsecret on Linux), not in a
  config file. `~/.config/openscale/` holds only the selected account and a cached
  "latest version" check. Verification and sign-in state are inspected with `osc doctor`.
- **Implementation shape** (recoverable from the stripped binary's function table): a thin
  `cmd/openscale/main.go` plus one `internal/cli` package holding the commands, HTTP client,
  credential store, money formatting, sandbox/template support, `doctor`, `upgrade` and shell
  completion. A small `internal/tunnel` package serves the sandbox forwarding features. There is no
  CLI framework dependency — argument parsing, help text and the JSON output envelope are
  hand-rolled. Dependencies are limited to TOML config, keyring/D-Bus access, a WebSocket client and
  terminal detection; no analytics or telemetry libraries are present.

### Distribution, installation and verification

Reference version: **0.1.7** (current). The plugin uses only long-standing commands and the `--json`
contract, so any version that supports them works; `osc version` and `osc doctor` report what is
actually installed.

| Item                       | Public location                                                               |
| -------------------------- | ----------------------------------------------------------------------------- |
| Installer script           | <https://openscale.so/install>                                                |
| Release archive            | `https://openscale.so/download/cli/v0.1.7/openscale_0.1.7_<os>_<arch>.tar.gz` |
| Published digests          | `https://openscale.so/download/cli/v0.1.7/checksums.txt`                      |
| Homebrew tap (first-party) | <https://github.com/afgventura/homebrew-tap>                                  |

The installer downloads the archive and `checksums.txt` and aborts unless the SHA-256 matches. To
verify by hand instead of running the script:

```bash
base=https://openscale.so/download/cli/v0.1.7
curl -fsSLO "$base/openscale_0.1.7_linux_amd64.tar.gz"
curl -fsSLo checksums.txt "$base/checksums.txt"
sha256sum -c --ignore-missing checksums.txt   # must print OK
tar xzf openscale_0.1.7_linux_amd64.tar.gz
install -m 0755 openscale ~/.local/bin/openscale
ln -sf openscale ~/.local/bin/osc
osc version && osc doctor
```

`brew install afgventura/tap/openscale` installs the same digests through a generated formula, a
second channel attesting the release.

The digests are the vendor's published values, not a maintainer-signed release. The plugin does not
bundle, mirror or redistribute the binary: users install it from the vendor.

### Output contract

`--json` is the stable, machine-readable form and the only form this plugin parses. Keys are
emitted in alphabetical order and errors use a uniform envelope:

```json
{ "error": { "code": "unauthorized", "message": "…", "exit": 3 } }
```

Codes map to distinct meanings (`unauthorized` = not signed in or key rejected), which is why the
plugin forwards CLI error text verbatim instead of inventing its own.

## 2. Commands used by the plugin

Three commands are used by the widget to obtain required data from two different hosts:
account data from the **web app's internal API**, and models data from the
**public product API**.

### A. `osc balance --json`

Reads the account's credit state (credit balance, rolling 24 h spend, remaining runway) from the
official **authenticated API endpoint `GET https://app.openscale.so/api/cli/balance`**.

Illustrative response — the figures below are not a real account:

```json
{
  "balanceUusd": 12345678,
  "spent24hUusd": 987654,
  "runwayHours": 431.25,
  "planCovered": false
}
```

The widget polls this for the bar figure; it is the cheapest account call and the only one
refreshed in the background.

`spent24hUusd` is a **rolling** 24 h window, so it will not match `usage --today`, which is a
calendar day.

### B. `osc usage {--today | --7d | --30d} --json`

Reads the account's consumption (requests, tokens used per model and costs) over
a given period from the official **authenticated API endpoint
`GET https://app.openscale.so/api/cli/usage?period=<today\|7d\|30d>`**.

The widget issues three commands with `--today`, `--7d` and `--30d` in sequence, so the
widget can show tokens used.

Illustrative response — the figures below are not a real account:

```json
{
  "period": "7d",
  "from": "2026-01-01",
  "requests": 128,
  "costUusd": 45210,
  "tokens": {
    "input": 1234567,
    "cached": 8901234,
    "output": 45678
  },
  "models": [
    {
      "model": "deepseek/deepseek-v4.1-flash",
      "tokens": 7654321
    },
    {
      "model": "z-ai/glm-5.3-flash",
      "tokens": 4321098
    },
    {
      "model": "muse/glimmer-30b",
      "tokens": 1200
    },
    {
      "model": "deepseek/deepseek-v4.1-flash:fast",
      "tokens": 55
    }
  ]
}
```

### C. `osc models --json`

Reads the models catalogue (id, name, context window, fast-mode availability, list prices)
from the official **public API endpoint `GET https://api.openscale.so/v1/models`**.

```json
[
  {
    "context": 1048568,
    "fastMode": true,
    "id": "deepseek/deepseek-v4.1-flash",
    "name": "DeepSeek: DeepSeek V4.1 Flash",
    "usdPerMillion": {
      "cached": 0.003,
      "input": 0.06,
      "output": 0.24
    }
  },
  {
    "context": 1048576,
    "fastMode": false,
    "id": "z-ai/glm-5.3-flash",
    "name": "Z.ai: GLM 5.3 Flash",
    "usdPerMillion": {
      "cached": 0.024,
      "input": 0.12,
      "output": 0.4
    }
  }
]
```

The real catalogue is longer; the widget groups these entries by vendor, cheapest input first.

The widget uses obtained JSON data to populate the "Models" tab, and caches the data
on disk for 24 hours.
